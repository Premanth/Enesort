# EcoSort v2

A hybrid in-place sorting algorithm with O(n log n) guaranteed complexity.  
Extends the EcoSort v1 dual-pivot quicksort with five performance fixes (F1–F6)
verified by a reproducible benchmark harness.

## Quick Start

### Prerequisites
- GCC ≥ 11 or Clang ≥ 14 with C++17
- CMake ≥ 3.18
- Python 3.9+ with `numpy pandas scipy matplotlib tabulate`
- (Linux) `linux-tools-generic` for `perf` hardware counters

### Build

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release -DECOSORT_FETCH_DEPS=ON
cmake --build build --parallel
```

### Correctness Tests

```bash
./build/test_correctness
# Full fuzz (1M arrays):
ECOSORT_FUZZ=1 ./build/test_correctness
```

### Smoke Benchmark (Step 3 deliverable)

```bash
mkdir -p results/raw
./build/bench --smoke --trials 5 --sizes 1000,10000,100000 \
    > results/raw/smoke_$(date +%Y%m%dT%H%M%S).csv
```

### Full Study

```bash
python3 scripts/run_all.py --trials 30 --sizes 1000,10000,100000,1000000
```

### Analysis

```bash
python3 scripts/analyze.py --results-dir results
python3 scripts/tables.py  --results-dir results
python3 scripts/plots.py   --results-dir results
```

### Docker Reproduce

```bash
docker build -t ecosort .
docker run --rm -v $(pwd)/results:/ecosort/results ecosort
```

Or via the `make reproduce` target:

```bash
make reproduce   # uses Docker
```

## Algorithm – EcoSort v2

EcoSort v2 is a dual-pivot 3-way partitioning quicksort with the following
fixes over v1 (each independently ablatable via compile-time macros):

| Flag | Feature | Fixes |
|------|---------|-------|
| F1 | Median-of-5 pivot sampling | Anti-quadratic on sorted/nearly-sorted |
| F2 | Equal-key fat partition | O(n·k) for k distinct keys |
| F3 | Depth-limit heapsort fallback | Introsort-style O(n log n) guarantee |
| F4 | Run/sortedness sub-range check | Avoids work on monotone runs |
| F5 | Configurable insertion cutoff (default 16) | Tunable base case |
| F6 | Smaller-two-first recursion | Stack depth O(log n) |

**Stability**: NOT stable.  
**Types supported**: `int32_t`, `int64_t`, `double`, `struct{int64_t key, payload}`.

## Benchmark Protocol

- 30 trials per cell; first trial discarded as warm-up
- Fresh input copy every trial; copy time excluded
- Pinned to one core (`taskset -c 0`) where possible
- Hardware counters via `perf_event_open` (cycles, instructions, L1d, LLC, branch misses)
- Verified sorted + multiset-equal every trial; abort on failure
- All numbers from logged runs; no invented data

## Workloads

20 deterministic seeded workloads including: uniform random, ascending, descending,
nearly sorted (10 swaps / 1% / 5%), sorted+100 appended, organ-pipe, sawtooth
(mod 4/16/64), few distinct keys (2/10/100), all-equal, all-equal-but-one, Zipf,
reverse+noise, blocks-ascending, and median-of-3 killer sequence.
